# R99 — 诊断算法设计智能：可解释 → 受限修订 → 成本绩效 → 独立实测门禁

**2026-10-25 · Draft / 研究功能。** 依赖 R98（及其 R93–R97 前置研究接口）。未修改 `main` Stable 的资格范围。

## 一、为什么这次优先改变设计智能，而不是增加算法库

`autogen` 必须解决“为什么选择这种诊断结构、为什么失败、如何合法修改、成本是否值得、是否在独立物理设备上优于固定基线”。R98 生成了振动时域、包络、测速阶次与记录级融合结构，但它们的 SOURCE TRAIN 内部留组结果**不能**被自动解释为外部泛化。

R99 不再创建分类器、不复制 `torch_like` 或 AAS 的监测算法，而是提供：

**研究设计侧：`design_review.explain_source_design(frozen_R98_plan, R98_source_report)`**

- 针对每种图，列出从设备合同可以核对的**结构准入理由**：包络需要合法振动采样频率，阶次需要真实**已登记测速来源**，融合需要原记录内的其他已登记标量。说明是条件解释，不是“包络带一定包含某类故障”的因果发现。
- 读取 R96 真正生成的源留组分数，标记：最差组准确率低于 0.5、组宏平均准确率低于 0.65、健康误报超过 0.2。**这三个阈值是固定的研究诊断提示，不是工业报警阈值、也不改变任何 `AAS` 检测器的报警后处理。**
- 后续动作只能引用**已经被冻结在 R98 研究计划内的候选方案**。高误报可建议对比已存在的低误报备选；复杂结构在 SOURCE 组失效，可建议退回预定义时域基线；所有结构都失败时，明确应补采独立设备数据而非无上限扩大网络复杂度。
- 每个修订都记录“没有新增模型架构”“没有调整算法阈值”“不是新的独立证据”“对源数据进行第二轮设计会增加选择偏差”。不能把训练集内部效果的提高宣称为外部独立改进。
- 输出 partial-cost Pareto：SOURCE 留组最差组准确率 ↑、健康误报 ↓、**已观测提供者 fit 时间** ↓，只把非支配候选标记为研究线索。单个候选的独立 FFT/预处理/推理时间、峰值原生内存、GPU/CPU差异和能源成本**未**完整计量，因此本轮不称为“计算资源公平匹配”。
- `resource_measure.measure_source_graph_end_to_end` **额外**以 `perf_counter` 和 `process_time` 对**整份候选图 SOURCE 实验**计时，包含原始信号处理、包络/FFT、折内预处理以及模型拟合/预测，并用 `tracemalloc` 标注 Python 分配追踪峰值。它不是“逐候选完整成本排名”：不会追踪 NumPy/SciPy C 扩展或 GPU 的全部分配，也不能据此比较在不同硬件上运行的性能；底层进程与设备功耗不在此收据范围。
- 研究计划、原始图、候选、预处理选择、分数组与试验收据均依照 SHA、ID 与原始方案逐项检查；冒用其他模型、混入第三方验证结果、伪造已通过独立评价或试图改变冻结图的请求一律拒绝。

- `measure_source_graph_end_to_end`：记录所有候选图作为**一份**源实验运行时，从 FFT/包络到提供者算法的总体 wall/CPU 秒数与受限 Python 内存采样；不宣称 FLOPs 与原生数组峰值已计量。

**独立评审侧：`independent_review.freeze_comparison` 和 `evaluate_sealed_measured_comparison`**

这是与 SOURCE 设计器完全分离的评审接口，设计器本身不接触任何 VAL/FINAL 标签。使用者在**获取验证标签前**冻结具体 challenger 与固定 baseline 身份、主指标和比较口径。

受信任的数据管理者提供 R93 完整清单、实际磁盘原始测量文件的路径（仅在评审主机上）、真实 heldout 预测与标签；工具重新计算**每个原始文件真实 bytes 的 SHA-256**，拒绝“只有元数据哈希但没文件”的输入。拒绝来自合成/仿真来源的独立实测声称；要求新物理设备分组 `unseen_physical_device`，所有 VAL 物理组与 TRAIN 物理组完全分离；每类至少 **3 台独立声明物理设备**；按整个原始物理设备求均衡的 group macro accuracy（而不是以窗口为独立样本），记录健康组误报以及配对独立组一侧**精确 sign test** 的 p 值。不允许用置信结果重新筛选 challenger/baseline。

评审输出的 `directional_submission_evidence_meets_preregistered_threshold` **仅表示对用户提交的预测流与测量标签的一项描述性统计判据**（正向组宏增益、配对 sign test p ≤ 0.05 且健康误报未增加），**不是**外部独立设备“已经证明算法更好”。本轮没有验证预测流确由被冻结的可执行模型产生、也没有设备序列号/来源的可信第三方签名，因此 `independent_real_device_superiority_proven`、`eligible_for_stable` 始终为 `false`。

### 现有“两份真实 CWRU”为什么不能替代独立验证

R97/R98 已在 GitHub Actions 验证过官方 CWRU **97.mat 和 109.mat** 的真实信号频带与包络特征。然而两份原始记录无法保证每类至少 3 个独立物理设备，也没有经过独立核验的测速通道和传感器/故障来源体系。因此它们只满足“算法能处理真实波形”的**特征层验收**，不能报出可推广至新轴承的算法优胜结论。

## 二、下一项真正的独立实测基准：Paderborn University Bearing DataCenter

公开原始来源：[Paderborn University KAt DataCenter](https://mb.uni-paderborn.de/en/kat/research/bearing-datacenter/data-sets-and-download)，有 6 组未损伤、26 组损伤轴承实验、不同运行条件、振动与电流以及转速等辅助测量。

**重要：** 这里有 32 种 bearing conditions/damage states，不能未经逐一核验就声称全部是独立制造序列号或真实现场自然故障。使用其机构的记录日志、轴承编号与论文对每个物理组做人工可信核对，再允许成为验收。数据 CC BY-NC 4.0，只适合遵循源许可的非商业研究；不得把它直接打包分发给商业甲方。

拟采用的严格工作流：

1. 从官方取得原始 MAT 与完整测量日志；由评估机计算真实 file SHA-256，标记真实原始 bearing 身份和故障类型（不要将同设备的 20 个 4 秒记录误认为 20 个独立轴承）；固化采样率、工况、真实可观察通道与不可信单位。
2. 按物理 bearing ID 进行 **TRAIN / 锁定独立 VALIDATION** 组拆分，人工审计同一 bearing 和原始文件 SHA 不跨组；在研究开始前明确健康/故障设备比例以及留出策略。不要将窗口随机分割为训练、测试。
3. 只在 SOURCE TRAIN 上运行 R93–R99 自动设计、受限修订及资源测量；对所有设计报告写入版本、种子、代码 SHA、真实物理分组及训练完整收据；定稿 challenger 和可比较的固定基线。
4. 受信任执行服务将**冻结的真实模型制品**和处理图部署到只读独立数据评估工作者，强制生成预测数组，逐个 SHA 与模型执行收据绑定；评估端才读取验证真值。此项执行端到端可信模型约束当前**尚未实现**，不可跳过。
5. 使用 R99 原始字节核验、严格物理分组与配对评价。记录最差组性能、健康误报、实际特征计算 + fit + 推理耗时、CPU/GPU 硬件记录、峰值内存与不确定性；多候选、多任务/多 seed 测试需事前安排多重比较修正，不允许试错后重用独立验证集。
6. 若数据不足、部署不可重复、模型制品来源不明、硬件成本不可比或提升统计支持不足，判定 **未证明优于固定基线**。负面结论是正确的科学结论。

**本次 R99 PR 不声称上述 6 步已经完成；它落实了研发解释/受限修订与数据可信性部分门禁。** 如官方数据过大或网络不可访问，首先建立原始测量下载日志与可信介质验证，不得改用低质量合成数据补足“独立实测”证据。

## 三、科研评审结论边界

| 研发阶段 | 当前 R99 实施 | 不允许声称 |
|---|---|---|
| 为什么生成结构 | 从受约束元数据解释包络、阶次和融合准入 | 已证明故障机理因果关系 |
| 为什么失败 | 固定源组指标与保守失败类型 | 根因已被因果定位 |
| 有约束改进 | 在冻结方案中建议已有备选，并拒绝未注册增长 | 改进算法已经在新独立样本证明 |
| 绩效/成本 | 已观测 fit 秒数、组指标、source-Pareto | FLOPs、峰值内存和特征总耗时公平 |
| 独立实测门禁 | 原始文件 SHA 校验、物理组审计、配对组指标 | 真实设备身份和冻结模型预测链已独立认证 |
| 正式优越性/Stable | 暂不符合 | 已产生工业通用 SOTA 或模糊优越性 |

## 四、复验命令

在 `source_product` 根目录（Windows PowerShell）：

```powershell
python -m pip install numpy scipy scikit-learn pytest
$env:PYTHONPATH = "src"
python -m pytest -q tests/phm_design/test_r99_design_review.py
```

CI 将进行 Linux 3.11 / Linux 3.12 / Windows 3.11 与 R93–R98 研究栈联合回归。所有测试都明确是**合成协议夹具**，其中的伪 `measured` 清单正用于证明“元数据和文件 SHA 都通过，仍然不足以认证真实工业设备身份或模型预测来源”。不将本地测试和公开测试样例写成实测算法优胜报告。

项目在没有本机工业设备的条件下依然可以靠官方公开测量开展真正研究；但只有充分独立的实测分组与可信执行链到位，才有条件发表“优于固定基线”的具体受限结论。
