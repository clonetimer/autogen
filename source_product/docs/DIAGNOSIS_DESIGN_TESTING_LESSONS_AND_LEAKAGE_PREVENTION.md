# 诊断算法设计与测试经验：防止数据泄露、评估污染与泛化误判

版本：1.0；日期：2026-10-14。

适用对象：卫星及其他工程系统的故障检测、部件定位、故障分类和端到端诊断；适用于人工研究、AutoML 与 AI Agent 自动设计。

本文是基于 R17 / Sat-CED 项目的复盘和后续流程建议，不是新的实验报告，也不表示下述门禁已经全部实现。文中区分“本次已核实事实”“尚未证实的风险”和“建议采取的措施”。

## 一、先记住六条底线

1. 测试反馈参与了特征、结构、阈值政策或后处理设计，即使没有训练权重，也已影响最终评估的独立性。
2. 名称隔离、文件哈希不重复和物理领域独立是三件不同的事，不能互相替代。
3. 仿真器能够输出的变量，不一定是部署时可获得的遥测；显式删除标签不足以证明特征合法。
4. 离线完整轨迹正确，不等于在线及时发现；故障条件下定位/分类正确，不等于端到端成功。
5. 100% 既不是泄露的充分证据，也不是算法可靠性的充分证据；应触发更严格核查。
6. 结果只能支持实际验证过的范围。重复使用的测试集应降级为开发集，不能通过改名或重新封存恢复盲测资格。

## 二、本次发生了什么

### 2.1 已核实的过程

数据角色为 TRAIN 84 条、VALIDATION 42 条、TEST 84 条、OOD 42 条；按现有命名分别有 6、3、6、3 个场景标识。这里的“场景数”不是已经验证的独立物理域数。

| 阶段 | 实际观察与动作 | 对评估的影响 |
|---|---|---|
| PHM / ModernTCN 对比 | 在既有 TEST/OOD 上观察到性能不足 | 后续算法设计已经知道这些集合上的结果 |
| 部件图网络 v1 | 未解决 OOD 健康误报 | 继续研究物理不变量证据 |
| 物理证据 v2 | 故障识别好，但下边缘阈值产生明显健康误报 | 触发阈值政策修订 |
| v3 | 保留权重，将阈值改为验证健康/故障分隔区间中点 0.52375 | 数值来自验证集，但选择政策受到研究测试反馈影响 |
| v3 扰动检查 | 部件定位正确，部分类型却跨部件；噪声/标定扰动端到端宏 F1 为 0.9464/0.9755 | 触发后处理修订 |
| v4 | 根据预测部件约束类型，已有清洁轨迹及指定扰动复评均为 100% | 规则受反馈启发，成绩不能当作无偏独立验收结果 |
| 复核与交付 | 接受降级，发布包标注开发复评版 | 保留成绩和失败记录，但收缩结论 |

以上过程可查：[完整迭代结果](SATELLITE_EVIDENCE_RESULTS.md)、[v4 设计](SATELLITE_EVIDENCE_V4.md)、[封存记录](../artifacts/satellite_evidence_v4/selection_freeze.json)、[交付降级声明](../packaging/sat_ced_v4/README.md)。

### 2.2 不能混为一谈的结论

- 已检查的训练路径中，健康参考和标准化由 TRAIN 拟合，检查点与候选组合由 VALIDATION 选择；未发现将 TEST/OOD 直接用于这些拟合的路径。
- 当前观测白名单及独立推理路径未发现直接使用文件名标签、故障时刻或仿真真实故障参数作为特征。
- 已确认测试复评和扰动反馈参与政策/规则设计。这是本次最明确的评估污染，不能被前两条抵消。
- 完整观测数组精确不重复检查曾通过；没有因此证明近重复不存在、基础物理配置独立或目标域超出训练支持范围。
- 当前 OOD 跨领域资格未证实；没有证据支持把同一仿真器生成的数据一律认定为不合格，也没有证据支持仅凭 OOD 名称认定其合格。

## 三、应防范的不只是“把标签喂给网络”

| 风险类型 | 工程诊断中的例子 | 应采取的控制 |
|---|---|---|
| 样本/家族重叠 | 同一基础世界的不同窗口分别进入训练与测试 | 先按物理世界/生成家族分组，再划分、切窗 |
| 标签与元数据捷径 | 文件名、故障事件、运行时故障计数、按标签生成的目录或通道 | 输入与真值分离；预测仅接收经契约验证的观测 |
| 预处理泄露 | 全数据拟合均值、PCA、健康参考、缺失值或特征筛选 | 每折仅在其训练部分拟合；验证/测试只做变换 |
| 未来信息泄露 | 在线检测使用故障后的完整轨迹、双向滤波或居中差分 | 按可用时间构建因果窗口；离线任务明确单列 |
| 测试驱动设计 | 看误报后改变阈值政策，看混淆矩阵后补规则 | 只在开发集迭代；最终测试独立托管与冻结 |
| 仿真真值代理 | “有效状态位”由注入器直接设置，而非真实设备检测产生 | 追溯生成路径和部署来源；有/无状态位双轨实验 |
| 生成模板捷径 | 各故障固定幅度、固定时刻、固定长度，模型识别模板 | 预先随机化、平衡无关因素，并覆盖弱故障和正常切换 |
| 目标域适配伪装 | 用 OOD 无标签统计量重新归一化，却声称完全未见域泛化 | 明确归类为适配/转导协议，并按该协议评估 |
| 指标筛选 | 只报最好的种子、场景或一项指标 | 预注册指标和聚合规则；保留全部尝试与失败 |

通用预处理原则可参考 [scikit-learn 数据泄露说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)。但使用 Pipeline 只能约束部分数据流，不能阻止研究者或 Agent 根据测试成绩修改算法。

## 四、算法设计应先有任务契约

训练前写清楚以下选择，不能在看到成绩后变更定义：

- 推理单位：单个时点、滑动窗口、完整轨迹，还是事件。
- 时间要求：离线诊断、在线报警、早期预警；可使用的历史长度和最大延迟。
- 定位粒度：子系统、部件族、具体设备、轴、支路或根因。不能把 ADCS/EPS 二分类写成部件定位。
- 故障范围：闭集已知类、未知故障、多故障；单故障类别库不自动覆盖同时故障。
- 允许输入：传感器、命令、状态位、估计量及其可用时刻、单位、精度和失效行为。
- 输出与失败行为：健康、故障、无法判断；缺失数据或证据不足时是否拒判。
- 部署先验：是否需要初始健康前缀、配对健康轨迹、设备标定参数或目标域校准。

阈值政策应预先规定目标，例如固定可接受误报约束下优化召回，或固定代价函数。若选择验证分隔区间中点，还必须事先规定无法分隔时的处理，不能只在数据恰好可分时宣布成功。

### 卫星部件先验应如何使用

可优先考虑陀螺—星敏一致性、飞轮转矩—轮速响应、太阳阵功率—日照关系、SOC 变化—净功率关系，以及 PDU 命令—使能—负载功率耦合。这些关系有助于减少对某一工况绝对数值的依赖，但其有效性是待验证的设计假设。

每个残差必须注明适用条件：星敏有效、轮速/功率有足够激励、SOC 未饱和、负载已使能、时间同步成立。没有激励时应标记“证据不可用”，不能把缺乏可辨识性当作健康。

应单独标注母线功率代理等间接证据；不能把代理特征解释成硬件电压、容量或转矩参数的精确估计。

## 五、数据划分：先隔离物理家族，再切窗口

### 5.1 推荐的数据角色

| 角色 | 允许用途 | 不允许用途 |
|---|---|---|
| TRAIN | 拟合参考、预处理、模型；构建训练增强 | 与最终测试共享基础轨迹或生成家族 |
| DEV-VALID | 早停、超参数、组合、阈值和规则选择 | 被称为最终测试 |
| DEV-STRESS | 研究噪声、模式切换、失效机制并修改设计 | 修改后仍称它为盲测 |
| FINAL-ID | 冻结后的独立同域验收 | 用其反馈继续选择后又报告无偏成绩 |
| FINAL-OOD | 冻结后的独立目标域验收 | 用目标域真值、错误案例或未声明的适配统计改设计 |

数据较少时，可采用按世界分组的嵌套验证：内层选择、外层估计整套选择程序的表现。任何针对外层结果的后续修订，也会降低其独立性。分组与时间相关性需进入验证设计。[交叉验证官方说明](https://scikit-learn.org/stable/modules/cross_validation.html)

### 5.2 世界身份不能由 split 前缀制造

本次代码把 `TRAIN-C0` 和 `OOD-C0` 视为不同标识，这只能保证命名不冲突。后续应建立不含 split 名称的基础世界身份，例如：

```text
base_world_id = hash(规范化的基础物理配置、初始条件、任务模式、基础噪声/扰动生成身份)
generation_family_id = 同一基础世界及其健康/故障/增强/重复运行的家族身份
```

这里是概念定义，不是已经实施的算法。规范化需固定单位、浮点表示、默认值和配置展开方式。故障标签、输出路径、时间戳或 split 字符串不能成为制造“独立世界”的依据。

同一世界的健康/故障配对轨迹、切窗、降采样版及增强版原则上留在同一角色。若研究问题允许不同协议，必须事先说明其依赖关系及允许的结论。改变随机种子也不自动构成新领域。

至少分四层检查：文件完全重复、观测数组完全重复、基础配置/生成家族重叠、近重复及共享片段。近重复判定阈值应在开发阶段确定，并报告合法相似性，避免事后任意剔除难例。

## 六、OOD 的资格不是由文件夹名决定的

域泛化关心的是未见目标域上的表现，模型选择协议本身也是问题的一部分。[DomainBed 原始研究](https://arxiv.org/abs/2007.01434)

为每次 OOD 评价准备一张“域差异表”：

| 变化轴 | 训练域记录 | 目标域记录 | 需要回答的问题 |
|---|---|---|---|
| 轨道与光照 | 轨道参数、食时长、姿态/日照关系 | 明确目标范围 | 只是相位不同，还是轨道/光照条件变化？ |
| 硬件动力学 | 惯量、轮惯量、摩擦、执行能力 | 明确目标范围 | 新组合、参数外推，还是不同设备族？ |
| 电源参数 | 发电尺度、容量、SOC 工作区间、负载模式 | 明确目标范围 | 初始条件变化还是机理/参数变化？ |
| 测量链路 | 噪声、偏置、带宽、延迟、丢包、量化 | 明确目标模型 | 是否有独立测量链变化？ |
| 控制与任务模式 | 控制器、目标姿态、调度及切换 | 明确留出模式 | 是否将正常切换误当故障？ |
| 故障机制 | 幅度、时长、起始时刻、渐变规律 | 明确留出方式 | 新幅度、弱故障、新组合还是未知类别？ |
| 仿真/实物来源 | 生成器、版本、建模假设 | 独立模型或实测来源 | 是否仅复用了同一理想化模板？ |

逐轴声明：同域新样本、训练范围内新组合、参数外推、模式留出、跨模型/硬件、仿真到实物。它们不是一条自动成立的等级链，也不能用一个轴的变化代表所有泛化。

合格的目标域证据至少包括：可核验参数差异、独立家族划分、目标数据未参与设计、足够的健康与故障场景，以及与宣称相符的评价协议。同一仿真器并不必然不合格；配置哈希不同也不必然合格。

对既有轨迹加噪声，只能支持指定幅度和模型下的扰动稳健性。若噪声未覆盖时间相关性、异方差、延迟、丢包、漂移与设备失效，不应宣称“真实噪声泛化”。

## 七、把盲测做成受控流程，而非口头承诺

以下为建议流程，需后续实现：

```text
任务/指标预注册 → 家族划分与输入契约 → 开发训练和压力测试
→ 冻结完整诊断流水线 → 独立数据托管与预测提交
→ 固定预测后解封真值评分 → 发布全部结果或降级并重新立项
```

### 7.1 冻结范围

不只冻结 `.pt`：同时冻结观测解析器、特征白名单、健康参考、标准化、窗口规则、残差公式、模型及集成权重、阈值数值与选择政策、后处理、拒判规则、评分代码、类别映射、依赖版本、随机种子和实验预算。

配置、源代码、模型和预测分别计算哈希。哈希证明内容一致，不证明此前未看过测试集；还需要访问记录和设计时间线。应覆盖完整传递依赖，不能仅哈希几个主文件就宣称整个流水线不可变。

### 7.2 权限与职责隔离

- 设计进程只挂载 TRAIN/DEV；最终数据不出现在其可读目录或会话上下文中。
- 数据托管方保管目标域和真值，按冻结协议提供观测；预测接口不得接收标签或含标签文件名。
- 评分方在预测文件固定后关联真值，执行预先冻结的评分。
- 无法人员分离时，至少使用独立账户/进程、访问控制、不可覆盖的运行目录和追加式日志。
- 保留原始预测、全部访问、失败运行和查询次数，不只保留最终最佳成绩。

如果目标域无标签适配是任务的一部分，应预先写明适配数据、更新范围和预算，并使用适配协议报告；不能一边读取目标统计量一边声称完全未见目标域。

### 7.3 看到测试结果后的处理

测试失败可以帮助科研，但使用反馈修改后的版本必须有新的独立验收依据：

1. 保留旧模型及其失败成绩。
2. 记录看过什么反馈、改了什么，以及为何修改。
3. 将已参与修改的测试/扰动数据标记为开发用途。
4. 冻结新版本；使用新独立数据或预注册的独立外层评估。
5. 不删除失败场景、不更改指标定义、不通过“再封存”恢复原测试集资格。

仅由预先指定的测试基础设施修复导致重跑，应有差异审查和理由；只要修改会影响预测或看到错误后选择了新策略，就不能当作纯基础设施重试。

## 八、AI Agent / AutoML 的额外风险

Agent 可以在文字推理中使用测试反馈，即使训练函数完全没有读取测试集。`test_used_for_selection=false` 只能描述被检查的程序路径，不能替代整段研究历史。

建议在任务指令中明确：

```text
本次只允许使用 TRAIN、DEV-VALID 和 DEV-STRESS 设计算法。
不得读取 FINAL-ID/FINAL-OOD 的样本、标签、汇总成绩或错误案例。
任何阈值政策、特征或后处理变更均须写入实验日志。
遇到最终测试失败，报告失败；不得自行修改后继续宣称盲测。
若发现已访问最终测试反馈，立即标记该版本为开发复评，保留证据。
```

提示词不是强制门禁，应结合目录权限、工具输入检查和日志。向 Agent 的摘要、记忆、子任务或后续对话转述测试错误，同样会传递信息。换一个 Agent、清空上下文或改随机种子，不能让已经据此修改的算法重新变成盲测设计。

文献检索与 SOTA 比较也须受预算约束：核验论文年份和官方实现；预先确定搜索与选择程序；未跑的候选只能称“候选”，不能列作已完成对照。

## 九、指标必须同时反映局部任务与整条链路

设真实故障状态为 D，预测为 D̂，部件为 L/L̂，类型为 C/Ĉ。

- 检测：召回、特异度、BA、精确率、误报率、漏检率；AUROC/AUPRC 可补充，但不能代替固定阈值性能。
- 条件定位：在全部真实故障样本上评价 L̂，不是只挑“成功检出的故障”。
- 条件分类：在全部真实故障样本上评价 Ĉ，并明确是否绕过检测门控以观察分类头。
- 端到端：检测为健康时输出健康，故障时输出预测类型；报告包含健康类的宏 F1 和混淆矩阵。
- 联合正确率：健康样本要求正确判健康；故障样本要求检测、部件和类型同时正确。
- 在线指标：事件级检出率、每小时/每轨误报事件、检测延迟分布和持续报警策略；未检出事件单列，不能只报已检出事件的延迟。
- 拒判：报告拒判率、覆盖率、拒判样本构成及总体失败，不得只在接受样本上报告高精度。

固定类别全集、宏平均方式、无样本类别处理和健康类是否参与。告警合并、持续时间、匹配容差及事件定义也必须预注册。多故障不能未经说明压成互斥单标签。

按场景报告均值、离散程度和最差场景。重复种子反映训练不稳定性，不增加独立测试世界数；同一世界下的 14 类轨迹也不等于 14 个独立领域。区间估计应尊重世界/设备聚类；世界太少时明确证据不足。零误报只代表观察样本中没有误报，不代表真实风险为零。

## 十、100% 应触发哪些诊断实验

以下检查先在开发数据上设计，并预先冻结；若根据最终测试检查结果修改算法，最终集需相应降级。

| 检查 | 目的 | 解释边界 |
|---|---|---|
| 移除/置乱文件名与元数据，保留观测 | 检验是否走标签/身份捷径 | 只测试被改变的路径，不是全部泄露证明 |
| 训练标签置乱，重新拟合全部监督步骤 | 排查异常捷径和评估错误 | 基线应符合不平衡与固定类集；单次低分不能证明无泄露 |
| 仅输入元数据或运行长度的负对照 | 排查生成模板 | 若意外高分，需调查而非直接删掉证据 |
| 移除状态位，仅用连续遥测 | 检验是否过度依赖自带故障提示 | 状态位若合法，可作为另一种输入条件单列 |
| 去掉物理残差、去掉层级约束 | 分离各模块贡献 | 同一部件只有一种类型时，层级规则会直接决定类别 |
| 相同通道、窗口、采样和搜索预算比较 | 分离信息优势与架构优势 | 工程全信息比较与架构公平比较分表 |
| 正常模式切换、弱故障、渐变、短暂异常 | 排查任务过易 | 幅度和分布应在开发阶段规定 |
| 全新物理家族与独立生成/实测链路 | 检查真正迁移 | 每个结果只支持对应目标域 |

卫星状态位审查要追踪到生产者：是设备自身有效性检测、控制软件状态、机载估计，还是注入器直接写出的开关。若业务允许使用内置自检，应明确比较“带自检信息的融合诊断”；不能将其包装为纯连续传感器诊断。

## 十二、发布门禁与泄露后的处置

### 12.1 发布前检查单

- [ ] 任务、输入条件、指标、拒判及在线/离线边界已冻结。
- [ ] 基础世界、生成家族、配对轨迹与窗口没有跨角色重叠。
- [ ] OOD 目标域定义及参数差异已核验，不只依靠目录名或哈希。
- [ ] 预处理、健康参考和每折拟合均只使用对应训练部分。
- [ ] 每个状态位/估计量有可部署来源和可用时刻证据。
- [ ] Agent、人员和搜索器没有用最终反馈选择设计；访问历史可查。
- [ ] 源码、权重、规则、阈值、依赖及评分契约均封存，预测先于真值关联固定。
- [ ] 失败尝试、全部预注册种子、场景结果与分母完整报告。
- [ ] 公平架构比较与全信息工程效果比较已区分。
- [ ] 结果措辞不超出目标域、样本量、时间要求和故障范围。

未满足某项不代表算法必然无效，但应阻止相应资格声明；不得用一个总 PASS 遮盖未检查项。

### 12.2 如果已经污染

停止将受影响成绩用作独立验收依据；保留模型、日志与预测；识别受影响的数据和决策；发布勘误/降级说明；冻结修改后的版本；申请新的独立评估。

若新数据尚不可获得，可以继续报告探索性成绩，但必须明确“开发复评，独立泛化未验证”。不能删除历史、只发布最后一次、把原集合改名成新测试集，或把哈希通过当作无泄露认证。

## 十三、本项目后续适用的结论与行动

Sat-CED v4 继续保留为开发复评交付物；当前压缩包及其 SHA-256 不因本文而改写。已有 TEST/OOD 不再承担后续版本的最终独立资格验证。

后续应优先补齐：基础物理配置与生成家族清单、OOD 参数差异证据、状态位部署来源核查、同输入条件对照、最终数据访问门禁，以及新物理世界盲测。本文中的模板与门禁尚未自动接入训练/评估脚本，需另行实现和验证。

本文按 scientific-writing 的结构原则分开事实、解释、限制和建议；方法学参考已在相关段落就近链接。经验的核心不是“以后不要出现100%”，而是：**无论成绩高低，都必须能证明这个结果来自怎样的数据、怎样的设计决策，以及怎样独立的评价过程。**
